# 조향 벤치 검증 — firmware/steering

조향 단계(1차 목표: RC 조향) 배선과 부품을 확인하는 방법과 결과.
설계와 검증 순서는 [조향 설계](../../01_development/01_firmware/02_steering_design.md) §6·§7,
회로는 [조향 벤치 회로도](../../02_guide/01_firmware/images/steer_bench_schematic.svg)를 본다.

- 수신기 핀 구조·연결 설명은 [RC 수신기 가이드](../../02_guide/01_firmware/02_rc_receiver_guide.md)를 본다.
- 이번 단계(§1–§3): 수신기 → Teensy(i-BUS), **Teensy → MUX → MDDS30 → 모터** 열린 루프 구동.
- 다음 단계: 센서를 차량에 단 뒤 effort 부호, 펄스 끊김 시 정지, hang 시험(개발 기록 9장).

---

## 1. i-BUS 대기 전압 — R5·R6 결정

Teensy 4.1은 5 V를 견디지 못하므로 i-BUS 선을 핀 15에 연결하기 **전에** 잰다
(`docs/build/03-electrical.md` §3.5.4 R5·R6 표, §3.5.1 RC 표).

**준비**

- 수신기 FS-iA6B에 **5 V만** 공급한다. B/VCC 줄의 **가운데 핀 = +**. Teensy는 연결하지 않는다.
- 송신기 FS-i6을 켜고 수신기 LED가 **깜빡이지 않고 계속 켜져 있는지** 확인한다(바인딩됨).

**i-BUS 포트 위치** (라벨을 바로 읽는 방향, B/VCC가 위)

- 채널 블록(CH1–CH6, B/VCC) 왼쪽에 따로 있는 **세로 1열**이다.
  - 위 3핀 = **i-BUS SERVO** → Teensy에 연결하는 포트
  - 아래 3핀 = i-BUS SENS → 텔레메트리 센서용, 쓰지 않음

**방법**

1. 도통(전원 끔): i-BUS 가운데 핀과 채널 블록 가운데(+) 열 사이에서 삐 소리가 나면 가운데 = +.
2. DC 전압(전원 켬, 검은 리드 GND): SERVO 3핀을 각각 잰다.

**판정**

| 신호 핀 값 | R5 | R6 |
|---|---|---|
| 약 3.3 V | 점퍼선 | 생략 |
| 약 5 V | 분압기 직렬 저항 | 분압기 GND 쪽 저항 |

- 가운데 핀은 **+5 V 전원**이다. 신호로 착각하지 않는다.
- 멀티미터는 평균값을 보여 주므로, 프레임이 오가는 동안에는 대기 전압보다 약간 낮게 읽힌다.

## 2. i-BUS 수신 — `ibus_monitor`

**연결:** SERVO 위 핀(신호) → Teensy 핀 15, SERVO 아래 핀(GND) → Teensy GND. 가운데(+)는 연결하지 않는다.
수신기 전원은 별도 5 V. 켜는 순서는 Teensy(USB) → 수신기.

**방법:** `firmware/bench`에서 `pio run -e ibus_monitor -t upload` → `pio device monitor`

| 확인 | 통과 기준 |
|---|---|
| 송신기 끔 | 줄이 계속 나오고 `NO FRAMES YET` (USB·스케치 정상) |
| 송신기 켬, LED 계속 켜짐 | **약 130 fr/s**, `bad 0`이 늘지 않음, `age … OK` |
| 채널 배치 | 스틱·스위치를 하나씩 움직여 어느 CH가 변하는지 기록. CH5(MUX SEL)는 2단 스위치여야 한다 |
| 송신기 다시 끔 | `NO FRAMES for … ms` 또는 값이 계속 옴(failsafe) — 어느 쪽인지 기록 (조향 설계 D2) |

## 3. Teensy → 모터 구동 — `pwm_effort_check`

Teensy가 내보내는 펄스가 MUX와 MDDS30을 거쳐 조향·구동 모터를 **각각** 움직이는지 본다.
위치 루프 없이 effort만 준다(`docs/build/04-firmware.md` §4.4). 배선은 [전체 배선 가이드](../../02_guide/02_power_wire/01_system_wiring_guide.md).

| 채널 | 경로 |
|---|---|
| 조향 | 핀 2 → PWM 1 → MUX **M1** → OUT1 → **RC1** → MLA·MLB → 조향 모터 |
| 구동 | 핀 3 → PWM 2 → MUX **M2** → OUT2 → **RC2** → MRA·MRB → 구동 모터 |

**준비**

- MDDS30 DIP `0 0 1 1 0 0 1 0`(`03-electrical.md` §3.5), 전원은 배터리에서 바로 25 A 퓨즈를 거쳐 `B+`·`B−`
- 바퀴를 띄운다. 송신기 SwA = **LOW**(MUX MASTER = Teensy)
- 켜는 순서: Teensy(스케치가 바로 1500 µs) → 수신기·MUX → **드라이버 마지막**

**방법**

1. `firmware/bench`에서 `pio run -e pwm_effort_check -t upload` → `pio device monitor`
2. 경로 전압(선택): `f`를 세 번 눌러 300 Hz로 올리고, 각 지점의 신호 핀을 멀티미터 DC로 잰다. 끝나면 `f` 한 번으로 50 Hz로 되돌린 뒤 드라이버를 켠다.
3. `S`(조향 사인), `D`(구동 사인)를 **따로** 보내고 어느 모터가 움직이는지 본다. 조향은 `3`/`6`(±0.15, 1초)이나 사각파로 양방향을 본다.

**통과 기준**

| 확인 | 기준 |
|---|---|
| 300 Hz 중립 전압 | 핀 2·3과 MUX M1·M2 약 1.5 V, MUX OUT1·OUT2와 RC1·RC2 약 2.2 V |
| 드라이버 시작 | ERR LED 꺼짐 |
| `S` | **조향 모터만** 양방향으로 움직임 |
| `D` | **구동 모터만** 양방향으로 움직임 |

- 도중에 겪은 문제(ERR 2번, 두 모터가 같이 돎, 채널이 바뀜, 조향만 안 돎)와 원인은 개발 기록 7.10에 있다.
